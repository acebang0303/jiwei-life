# 实现现状对照（2026-10-12）

用途：`docs/superpowers/` 下是 2026-08-26 ~ 09-03 的**设计 / 实施记录（历史快照）**，保留当时的决策过程有价值。
本文列出「设计文档里的说法」与「当前代码」已经分叉的点。**有冲突时以本文 + 代码为准**，每条都能在代码里找到对应实现。

## 1. 秒杀熔断器：固定窗口 → 真滑动窗口

- 设计文档说法（`plans/2026-08-26-market-seckill-shortlink.md`、`specs/2026-08-26-wheel-integration-design.md`）：
  「固定窗口简化版」环形计数，并把「窗口边界跳变」列为已知瑕疵、留待修复。
- 当前实现：`market/seckill/breaker/RedisCircuitBreaker` 已改为**真滑动窗口**——
  `windowMillis` 切成 `bucketCount` 个时间片环形轮转，判定时汇总最近一个完整窗口（`windowSnapshot()`）。
  新增 `minimumCalls` 低流量保护：样本不足时**不判熔断**，避免 1 次失败就 100% 跳闸。
- 配置字段变化：`windowSize` **已不存在**，改为 `windowMillis / bucketCount / minimumCalls`。
- 可测性：时钟可注入（`withClock` 静态工厂；Spring 用 `@Autowired` 显式标注唯一构造器），
  滑动窗口行为用可控时钟做**确定性**单测，不靠 sleep。

## 2. 注解式限流：语义澄清 + 多实例额度

- 设计文档说法：`RateLimitAspect` 的「滑动窗口」，注解字段名 `permitsPerSecond`。
- 当前实现：字段改名 **`permits`**（与 Redisson `RRateLimiter`「每 interval 个许可」语义一致）；
  注释明确为**固定窗口**（不冒充滑动窗口）；本地降级桶换有界 Caffeine（防 key 爆炸）。
- 多实例额度：新增 `seckill.ratelimit.degrade-instances`，Redis 故障降级到本机桶时
  **额度按实例数摊薄**，避免 N 实例把总限额放大 N 倍。

## 3. 短链：热路径异步化 + 全局限流

- 设计文档说法：重定向走 Caffeine「三级链路」，每次重定向异步写库更新 `click_count`；
  生成接口用 Caffeine 固定窗口限流。
- 当前实现：
  - `component/ClickCountBuffer`——重定向热路径只累加内存，5s 一次 `CASE WHEN` 批量 UPDATE，
    失败回滚内存计数待下次重试（不再「一次请求一次写库」）。
  - `ShortLinkService.resolve` 去掉 `@Transactional`（只读热路径不必占事务）；
    `create` 去掉 `@Transactional`——原实现「事务内 catch DuplicateKeyException 再查已有记录」
    会让事务进入 rollback-only，并发同一条长链的请求会 500。
  - 生成接口限流改为 **Redisson 全局令牌桶**（额度不随实例翻倍），本地 Caffeine 桶仅作 Redis 故障降级。
  - 长链**协议白名单**（仅 http/https）；默认**不信任** `X-Forwarded-For`（防伪造 IP 绕过限流）。
  - schema 里 `url_hash` 是**普通索引**，不是唯一索引（唯一性由 `uk_short_code` 保证）。

## 4. 点赞：以 DB 为账本 + Lua 原子 + 多实例安全

- 设计文档说法（`plans/2026-08-26-social-like-system.md`）：
  `reconcileLikeCount` 「对账整刷：**直接覆盖为 Redis 权威计数**」；`NoteLikeStore.applyDirect(...)`。
- 当前实现（**方向反了，这是重点**）：
  - `SyncReconciler` 改为**以 DB 为唯一账本**，用 DB 计数修正 Redis。
    原因：写路径是「先加 Redis → 再异步落库」，存在「Redis 已加、DB 未加」的在途窗口；
    若用 Redis 覆盖 DB，消费者随后再落一次库就会把计数**永久推高**。
  - 落库幂等：增量不取「事件条数」，而取 **SQL 实际影响行数**（INSERT IGNORE / DELETE 的影响行数之差），
    at-least-once 重放时增量为 0（`NoteLikePersistService`）。
  - 原子性：非热点路径改 **Redis Lua 原子切换**（`resources/lua/note_like_toggle.lua`），
    把「查是否已赞 → 翻转 → 改计数 → 推事件」放进同一段脚本，消除同一用户并发双击的 read-then-write 竞态；
    热点批量刷写同样走 Lua（`note_like_flush.lua`），按 SADD/SREM **实际结果**算增量。
  - 多实例：消费端与对账共用 **Redisson 分布式锁**（`NoteLikeSyncLock`）——
    原 peek + LTRIM 的实现在多实例下会重复消费。
  - 预热顺序：`LikeCountWarmUpRunner` 先 `drainAll()` 重放滞留事件，**再**以 DB 基线预热。
- 接口变化：`NoteLikeStore.applyDirect(...)` 已被 `toggle(...)`（原子切换）与 `flushAggregated(...)`（批量）取代。

## 5. NL2SQL 只读：从「配置」到「实测 + fail-fast」

- 设计文档说法：建只读数据源 + 表级白名单。
- 当前实现（三层全部落地并实测）：
  - `db/08_ai_readonly_user.sql`：`jiwei_ai_ro` 仅 SELECT / SHOW VIEW（实测 `CREATE` 被拒 errorCode 1142）；
  - `BizDbConfig`：连接级 `readOnly` + `allowMultiQueries=false` + `max_execution_time`；
  - `BizDbReadOnlyCheck`：**启动写探针自检**，`biz-db.read-only-check.fail-fast=true`（默认）
    时，一旦确认连接可写就**抛异常拒绝启动**（`false` 则仅打 ERROR 告警）。
- 实测发现（值得记住）：`readOnly` 连接下是 **MySQL Connector/J 在客户端**先拒掉 DML
  （报文 `Connection is read-only. Queries leading to data modification are not allowed.`，errorCode=0），
  语句根本到不了服务端，因此拿不到 MySQL 的 1792。自检需同时识别
  「服务端只读事务 1792 / 服务端权限 1142 / 驱动客户端拦截」三种形态。
  也就是说「只读」实际是**两道独立防线**。
- 故障注入验证：`readOnly=false` 时探针会**成功** → 判定可写 → fail-fast 生效（见测试与实机对比实验）。

## 6. SqlValidator：补 DOTALL + 语句白名单

- 设计文档说法（`plans/2026-08-26-ai-service-rewrite.md` 的 Task 6）：
  `INJECTION_PATTERNS` + `FORBIDDEN_KEYWORDS` 黑名单正则 `(?i).*\b(DELETE|UPDATE|...)\b.*`。
- 当前实现：该正则**缺少 DOTALL**——实测带换行的 SQL（`SELECT 1\nDELETE FROM ...`）会让整条黑名单**静默失效**，
  已加 `(?s)`；表名提取重写为「FROM/JOIN + 逗号连接 + 任意 schema 限定 + 反引号」三路收口；
  新增**语句白名单**（只放行 SELECT / WITH / SHOW / DESCRIBE / EXPLAIN）。
  实测证据见 `SqlValidatorTest`。

## 7. RAG 检索：补齐关键词通道 + RRF + 重排 + 降级

- 设计文档 / 原代码注释说法：「BM25 关键词 + 语义向量 → RRF 融合 → LLM 重排」。
- 当时的实际状态：**只有单路向量检索**，注释与实现不符，RAG「混合召回」名不副实。
- 当前实现：
  - 关键词通道用 **pg_trgm**：`ILIKE` 子串命中 + `%`（标题模糊），并把 GIN trgm 索引建成
    与查询谓词一致的**列索引**（EXPLAIN 实测 `Bitmap Index Scan`）；
  - **为什么不用 tsvector/BM25**：中文没有天然分词边界，`to_tsvector('simple')` 会把整句当**一个** token，等于失效；
    而「子串是否出现」对中文关键词恰恰最有效；
  - `RrfFusion` 融合两路 → `LlmReranker` 大模型重排（只认候选内真实 id，失败回退 RRF 顺序，不抛异常）；
  - Embedding 故障时自动降级为关键词召回；**删除了原来硬编码的假数据降级**（编造检索结果比不降级更糟）。

## 8. Agent / SSE：升级为 token 级流式

- 设计文档说法：`SseEmitter` 推送式流式输出。
- 当前实现：升级为 **token 级流式**——监听底层 flux 取逐 chunk delta，聚合器只用于产出最终响应；
  依据是用 `javap` + 诊断测试确认 `ChatClientMessageAggregator` 返回的是**合并后的终值**而非逐 chunk delta；
  流式链路异常自动降级为**阻塞调用**；模型 key 未命中时按 `agent.default-model` 降级。
